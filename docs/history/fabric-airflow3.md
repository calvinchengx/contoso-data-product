## Current entry

**THE FAMILY'S FIRST BI-FACING OUTPUT, and the first time its numbers are reached through a client that is not SQL.** A Direct Lake `SemanticModel` over warehouse gold, published by the DAG and queried back through Power BI's `executeQueries`: `Revenue USD 129341157.6700 · Cancelled Revenue USD 2800504.4000 · Sale Lines 474044.0000`, each **DAX == SQL** on the same run (`verify__20260820T110647Z`, 33 tasks, exit 0). The definition is core's (`contoso_product.semantic`, v0.4.0) and the BINDING is the leaf's, because core names no engine. **The contract reads gold TWICE rather than asserting the family's constants** — three sums over TDS against the same three measures over DAX — because a constant would match while the model was bound to the wrong warehouse, an empty schema or yesterday's entity, and comparing two paths of the SAME run cannot. **De-risked before it was written**: a probe published the shape against a live stack and got both numbers to the cent, twice, the second time on gold dbt had just dropped and recreated — so no emulator capability was added for this. **The core pin moved v0.2.0 → v0.4.0** in the same PR, two releases, across silver SQL changes (dialect macros, the explode fix); `product_snapshot.json` is byte-identical, which is the claim that bump had to prove. **The witness found two defects in the new code and both are worth the row**: the Direct Lake URL was built by rewriting the control-plane host and carried its `:9443`, refused as `InvalidDataset` — a message reading as MISSING when the URL was malformed — **and its test passed while it was broken**, asserting the host was present rather than the whole string; and money was compared for bit equality on the reasoning that "a difference is a wrong binding, never float error", which one line falsified (`dax 129341157.67000003` / `sql 129341157.6700`) because DAX arrives as an IEEE754 double while TDS returns DECIMAL. Both sides now quantize to the warehouse's scale and a cent still fails. **Still open, flagged not smuggled:** core declares the money columns `double`, which sits badly beside its own `money_is_never_stored_as_float` contract and would matter on real Fabric — a core release, not a leaf edit. [leaf#3](https://github.com/calvinchengx/contoso-data-product-fabric-airflow3/pull/3).

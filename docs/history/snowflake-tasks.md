## Current entry

**DoD 3 is CLOSED: the whole medallion runs THROUGH Snowflake Tasks.** `make verify` exit 0 from EMPTY VOLUMES against the **published** `snowflake-emulator:0.3.1`: bronze **28 tasks** (580,719 rows by `COPY INTO` over a stage prefix), silver **2 tasks** `PASS=13`, gold **2 tasks** `PASS=53`, and `129341157.6700 / 2800504.4000 / 474044` — **the family's figures to the last digit**, so moving the medallion onto Tasks moved no number. A task body is one statement and there are no stored procedures, so a step of N statements is N tasks chained with `AFTER`; that is not a workaround but how Snowflake expresses a dependency, and it is what gives this cell what every other cell got from its scheduler: **a failure recorded against a named node, its dependents recorded SKIPPED naming what failed them, and TASK_HISTORY answering afterwards.** Contract names come from `run_results.json` fetched out of the stage with `GET`, so they are what dbt EVALUATED rather than a glob of filenames (the G29/G41 property, kept). **G6's estimate was wrong in the way that matters**: it called the emulator half done and the leaf the remainder. The leaf was a day; underneath it were **six emulator changes**, every one found by running a real pipeline rather than a probe, and every one green on the parity table beforehand — a manual task ran a TRUNCATED body and reported SUCCEEDED ([#49](https://github.com/calvinchengx/snowflake-emulator/pull/49)); a task body was a duckdb statement, so streams never expanded and `COPY INTO` never rewrote ([#50](https://github.com/calvinchengx/snowflake-emulator/pull/50)); `EXECUTE DBT PROJECT` did not exist ([#52](https://github.com/calvinchengx/snowflake-emulator/pull/52)); a prefix `COPY INTO` was refused, which alone would have made bronze thirty-odd tasks ([#53](https://github.com/calvinchengx/snowflake-emulator/pull/53)); `GET` did not exist, so nothing could read dbt's own record back ([#56](https://github.com/calvinchengx/snowflake-emulator/pull/56)); and the emulator's dbt was a **2.0 PRERELEASE** that rejected gold with 11 validation errors, where Snowflake runs 1.9.4 ([#57](https://github.com/calvinchengx/snowflake-emulator/pull/57)). **The two that generalise:** three of these only ever failed on a SECOND run — the shape a scheduled graph meets on day two and a demo never does — and the emulator being STRICTER than the tenant is as bad as being looser, because a consumer concludes its own project is wrong. **It also moved core** (v0.6.0, [#34](https://github.com/calvinchengx/contoso-data-product/pull/34)): gold read `env_var('CONTOSO_SILVER_DATABASE', env_var('LAKEHOUSE_ID'))`, and Snowflake's dbt Projects refuse any key that is not UPPERCASE and `DBT_`-prefixed — *"enforced on every run. If you break them, the run fails"* — so gold could run on every engine here except the one named for running dbt as a first-class object. The nested default went with it, closing the eager-evaluation trap this plan already wanted gone.
